## 2026-10-25 — PostgreSQL (в процессе)

**Сделано**
- PostgreSQL 17 в docker compose: named volume `pgdata`, healthcheck через `pg_isready`
- `api` стартует только после готовности БД (`depends_on` + `service_healthy`)
- Секреты вынесены в `.env` (не в git), шаблон — `.env.example`
- SQLAlchemy: `engine` с пулом соединений, сессия на запрос через `Depends(get_db)`
- `/ready` теперь проверяет и модель, и БД (`SELECT 1`)

**Проблемы и решения**
- *`role "chat" does not exist` при подключении с компьютера.* Порт 5433 слушали два процесса: Docker и локально установленный PostgreSQL. Windows отдавала соединения на `127.0.0.1` локальному Postgres. Нашёл через `netstat -ano | findstr 5433`, перевёл контейнер на порт 5434.
- *`/ready` зависал при остановленной БД.* У подключения не было таймаута, и psycopg ждал бесконечно. Добавил `connect_timeout=3` — теперь `/ready` быстро отвечает `503`.

## 2026-10-21 — Docker

**Сделано**
- Dockerfile на `python:3.14-slim`, CPU-сборка PyTorch через `--extra-index-url`
- Порядок слоёв: сначала зависимости, потом код — пересборка после правки кода занимает секунды
- Сервис запускается не от root
- Модель не в образе, а подключается через bind mount `./models:/models:ro`
- Healthcheck на `/ready` через Python (в slim-образе нет `curl`)

**Замеры**
- Образ: 327 МБ сжатый, 1.53 ГБ на диске (почти всё — PyTorch)
- Память: ~325 МБ в простое, ~450 МБ при генерации

**Выводы**
- На VPS сейчас свободно ~350 МБ — сервис не поместится. Варианты: освободить память, swap, тариф 2 ГБ.

## 2026-10-17 — FastAPI

**Сделано**
- Модель загружается один раз в lifespan и хранится в `app.state`
- `/health`, `/ready`, `POST /chat`
- Pydantic-схемы с ограничениями параметров (temperature, top_k, max_new_tokens)
- Настройки через pydantic-settings и переменные окружения
- Слишком длинный вопрос (больше контекста модели) → `422` с понятным сообщением

**Решения**
- `/chat` объявлен через `def`, а не `async def`: генерация нагружает CPU и в event loop заблокировала бы весь сервер. FastAPI выполняет `def`-эндпоинты в пуле потоков.

## 2026-10-14 — ML-пакет

**Сделано**
- Код модели и генерации перенесён из ноутбуков в пакет `app/ml/`
- `ChatGenerator`: модель, токенизатор и `eot_id` в одном объекте вместо глобальных переменных
- Консольный чат `scripts/chat_cli.py` с замером скорости

**Замеры**
- ~18 токенов/с на ноутбуке (6 потоков), без KV-кэша; загрузка модели ~0.9 с

**Проблемы и решения**
- *`No module named 'app'`* при запуске файла напрямую. Скрипты запускаются из корня через `python -m`, чтобы пакет `app` был в пути поиска модулей.
- *Чекпоинт скачивался архивом.* Файл `.pt` — это zip-архив; распакованная папка не загружается, нужен исходный файл.
